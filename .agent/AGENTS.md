# AGENTS.md — AI agent guide for Paila

Paila is a Next.js 16 (App Router, Turbopack) + React 19 + TypeScript travel platform for Nepal. This guide lives in `.agent/` (tracked in git). A root `AGENTS.md` may be auto-regenerated by `next dev` — it is gitignored; keep the real content here.

## Docs (mandatory)

All project docs live in `docs/`:

- `docs/CHANGELOG.md` — Keep a Changelog format, dated entries
- `docs/CONTRIBUTING.md` — setup, scripts, conventions

**Strict rule for AI agents:** before changing code, read `docs/CHANGELOG.md` and any relevant doc in `docs/`. After every completed change, update `docs/CHANGELOG.md` under `## [Unreleased]` (one bullet per change, grouped Added/Changed/Fixed/Removed) and fix any doc in `docs/` the change made stale. Never commit a code change without its changelog entry.

## Commands

Package manager is **Bun** (pinned `bun@1.4.0` via `packageManager`). Never use npm/yarn/pnpm.

| Command | Purpose |
| --- | --- |
| `bun run dev` | Dev server (Turbopack, port 3000) |
| `bun run build` | Production build |
| `bun run typecheck` | `tsc --noEmit` |
| `bun run lint` | ESLint |
| `bun run format` / `format:check` | Prettier write / check (CI enforces check) |
| `bun run test:e2e` | Playwright smoke suite (38 tests, desktop + mobile Pixel 5) |

Run `typecheck`, `lint`, and `test:e2e` before committing. CI runs all plus `format:check` and `build`.

## Demo mode

The app runs with **zero env vars**: `src/integrations/supabase/client.ts` provides an in-memory Supabase stand-in (dev only). Guards: `isDemoMode()`, `isSupabaseConfigured()`, `isDemoEnabled(name)` in `src/lib/server/guardrails.ts`. Real Supabase activates when `NEXT_PUBLIC_SUPABASE_ANON_KEY` is set. Env reference: `.env.example`.

## Structure

- `src/app/(app)/` — authenticated app routes (guarded by `src/proxy.ts` session check)
- `src/app/(admin)/admin/` — admin routes (role-guarded in `src/proxy.ts`)
- `src/app/(onboarding)/`, `src/app/(public)/` — auth/onboarding flows
- `src/app/api/` — route handlers (`scan`, `translate`)
- `src/lib/actions/` — server actions (bookings, geocode, nearby-places, compute-route, search-places, place-context, admin-guide-verifications)
- `src/lib/data/` — static data modules behind a barrel; import via `@/lib/data`, never deep paths
- `src/lib/server/` — server-only helpers (mapbox, translate, ai, guardrails)
- `src/components/views/` — route-level client views
- `src/components/layout/` — `AppShell`, `AppShellNavigation` (drawer, bell, SOS FAB, sync dot)
- `src/components/ui/` — primitives (`page-primitives.tsx`: PageFrame/PageHeader/SectionHeader/Surface)
- `src/locales/<locale>/common.json` — 25 locales
- `src/proxy.ts` — middleware: route guards + auth session handling
- `supabase/migrations/` — schema; apply in timestamp order

## Conventions

- **i18n**: every user-facing string goes in all 25 locale files (`src/locales/*/common.json`). Validate JSON after edits.
- **Styling**: Tailwind v4 tokens in `src/styles.css` — terracotta/pine palette, `shadow-card/card-md/tactile/float`, `rounded-card/sheet/modal`. Use tokens, not raw hex.
- **Auth/authz**: guards in `src/proxy.ts`; admin checks via `requireAdmin()` in server actions; RLS enforces owner-only data. Never bypass RLS with the service role key on client-reachable paths.
- **CSP**: defined in `next.config.ts`; `'unsafe-eval'` only in development (React dev needs it). Mapbox domains whitelisted.
- **No nested interactive elements**: buttons must not contain buttons/links (a11y, enforced by e2e).
- **Commits**: conventional-commit style (`feat:`, `fix:`, `chore:`, `ci:`, `docs:`, `build:`), one focused change per commit.

## Security (mandatory)

- **Secrets**: never commit secrets; env vars only (`.env.local`, gitignored). `SUPABASE_SERVICE_ROLE_KEY` and `OPENAI_API_KEY` are server-only — never expose via `NEXT_PUBLIC_*` or client bundles. New server env reads go in `src/lib/server/` or route handlers, and must be added to `.env.example`.
- **Auth/authz**: every new route under `(app)`/`(admin)` inherits `src/proxy.ts` guards — verify it. Server actions must re-check auth server-side (`requireAdmin()` for admin paths); never trust client-supplied user IDs for ownership checks.
- **RLS**: new tables need RLS policies in a migration; owner-only by default. Never use the service role key to bypass RLS on client-reachable paths.
- **CSP**: keep `next.config.ts` strict; no new `unsafe-*` sources, no inline scripts. New external domains (maps, fonts, APIs) must be whitelisted explicitly.
- **Input**: validate at trust boundaries (route handlers, server actions). No `dangerouslySetInnerHTML` without sanitization.
- **Supply chain**: run `bun audit` after any dependency change; fix or justify findings before committing. Prefer `bun audit fix` within ranges; cross-major bumps need a test pass.
- **Demo mode**: `isDemoEnabled()` flags must stay dev-only (`NODE_ENV !== "production"` guard in `src/lib/server/guardrails.ts`) — never let demo shortcuts ship to production.

## Gotchas

- Repo root is the nested `Paila/` folder — terminals often land in the parent; `cd Paila` first.
- `next.config.ts` changes need a dev-server restart.
- Root `AGENTS.md`/`CLAUDE.md` are gitignored stubs; `next dev` regenerates them. The real guide is this file (`.agent/AGENTS.md`, tracked).
- Playwright `webServer` runs `bun run dev` and reuses an existing server on :3000 — kill stray dev servers if e2e behaves oddly.
- `test-results/` and `playwright-report/` are gitignored; CI uploads them as artifacts on failure.
