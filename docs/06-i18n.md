## Setup

- i18next + `react-i18next`, single `common` namespace, configured in `src/lib/i18n.ts`.
- Detection order: `localStorage("paila.lang")` → `navigator.language` (exact then language-prefix match) → `en-US`.
- Fallback language: `en-US`. `useSuspense: false` so pages render without translation gates.
- Language choice persists and sets `<html lang>` + `dir` (`rtl` for Urdu and Arabic).

## Locales

25 packs in `src/locales/<code>/common.json`: en-US, en-GB, ne, hi, mai, bho, new, thl, bo, bn, ta, ur (RTL), zh-CN, ja, ko, th, id, vi, ar (RTL), es, pt-BR, fr, it, de, ru.

## Coverage — know the gap

The shell (nav), hotels, and onboarding are translated. **Several high-stakes flows still have hardcoded English**: SOS panel, BookingModal, error/empty states, settings. When localising a flow, extract its strings into `common.json` with a stable key prefix (e.g. `sos.`, `booking.`) rather than inline literals.

## Adding a language

1. Create `src/locales/<code>/common.json` (copy `en-US/common.json`).
2. Import and register it in `src/lib/i18n.ts` (both the `LANGUAGES` array — with `flag`, `label`, `rtl` — and the `resources` map).
3. Set translations for the covered keys; missing keys fall back to `en-US`.

## Rules

- Never call `i18n.changeLanguage` directly — use `setLanguage()` so persistence and `dir` stay in sync.
- Interpolation: `t("key", { count })`; `escapeValue: false` is set, so never interpolate untrusted HTML.
- LanguageSwitcher is a full keyboard menu (Escape, arrows, focus return); reuse it rather than building another picker.
